# renderizado-pdf — LaTeX visual rendering skill

Produces the final PDF representation of the report generated by the `informe` skill.

Unlike a conventional LaTeX compiler, this skill does **not** require compiling `main.tex` with `pdflatex`, `latexmk` or another LaTeX engine.

Instead, it reads the LaTeX source and its associated assets, interprets the document structure and formatting, and reconstructs the final document as a PDF.

The objective is that the resulting PDF **looks and reads as if the `main.tex` had been compiled normally**, while avoiding the requirement for a LaTeX installation or LaTeX compilation environment.

---

# Relationship with `informe`

The two skills form a two-stage document-production workflow:

                 informe
                    │
                    ▼
        LaTeX report project
                    │
          ┌─────────┴─────────┐
          │                   │
      main.tex            assets/
                              │
                           Figures/
                              │
                              ▼
                    renderizado-pdf
                              │
                              ▼
                       visual rendering
                              │
                              ▼
                          main.pdf

The responsibilities are strictly separated.

## `informe`

The `informe` skill is responsible for:

- Writing the academic content.
- Structuring the report.
- Using the UEV LaTeX template.
- Configuring the subject, title, author, university and degree.
- Adding figures.
- Adding equations.
- Adding tables.
- Adding references.
- Adding code listings when necessary.
- Producing `main.tex` and its required assets.

## `renderizado-pdf`

This skill is responsible exclusively for turning that prepared project into the final PDF.

It must:

- Read `main.tex`.
- Interpret its structure.
- Interpret the formatting defined by the template.
- Load referenced images and assets.
- Render figures.
- Render mathematical expressions.
- Render tables.
- Render references.
- Reproduce the title page.
- Reproduce the UEV logo.
- Reproduce headings, spacing and page layout.
- Generate the final PDF.
- Verify the visual result before delivery.

It must **not** take over the responsibilities of `informe`.

---

# Core principle

The `.tex` file is the **source of truth**.

The renderer must treat LaTeX commands as instructions describing the structure and appearance of the final document.

For example:

\section{Principles}

must become a visually appropriate section heading.

Likewise:

\begin{equation}
E = mc^2
\end{equation}

must become a properly typeset mathematical equation in the PDF.

The final PDF must never expose raw LaTeX commands when those commands have a visible formatting equivalent.

For example, the user must not see:

\section
\textbf
\frac
\alpha
\SI
\si

in the final document.

# Workflow

## 1. Collect the complete project

Locate the complete project generated by `informe`.

The expected structure is:

main.tex
assets/
    LogopequeUE.jpg
Figures/
    ...

The project may also contain:

- Additional `.tex` files.
- `.bib` bibliography files.
- Additional images.
- Other local resources referenced by `main.tex`.

Do not assume that `main.tex` is self-contained.

Inspect the source for references such as:

\input{...}
\include{...}
\includegraphics{...}
\addbibresource{...}

and locate the corresponding local files.

If an essential dependency is missing, do not invent a replacement.

Report the missing dependency clearly.

---

Interpret the document sufficiently to identify:

- Document configuration.
- Page size.
- Margins.
- Font configuration.
- Colours.
- Section hierarchy.
- Title page.
- Logo placement.
- Paragraphs.
- Line breaks.
- Equations.
- Tables.
- Figures.
- Captions.
- References.
- Lists.
- Page breaks.
- Headers and footers.
- Custom commands.
- Environments used by the UEV template.

The renderer does not need to implement every feature of the LaTeX language.

It must correctly interpret the functionality actually used by the `informe` template and the reports generated from it.

# Visual equivalence

The central objective is:

Produce a PDF that visually matches the report that would have resulted from compiling `main.tex` with the intended UEV LaTeX template, as closely as the available PDF rendering capabilities allow.

The renderer must not simply extract text and place it into a generic PDF.

It must reconstruct the document's formatting and hierarchy.

For example:

\section{Principles}

must not become an arbitrary plain-text heading.

It should appear using the corresponding visual style defined by the template.

Likewise:

\begin{figure}[H]
    \centering
    \includegraphics[width=0.55\textwidth]{Figures/result.png}
    \caption{Experimental result.}
\end{figure}

must become a properly positioned figure with its caption beneath it.

---

# Template preservation

The visual style defined by:

assets/plantilla.tex

is the authoritative visual reference.

Do not redesign the template.

Preserve, as closely as possible:

- Page dimensions.
- Margins.
- Typography.
- Heading hierarchy.
- Heading colours.
- Paragraph spacing.
- Title-page design.
- Logo position.
- Figure sizing.
- Figure placement.
- Caption formatting.
- Equation presentation.
- Page numbering.
- References.
- Tables.

Do not replace the UEV template with a generic academic-document style.

---

# Content preservation

The renderer must preserve the academic content produced by `informe`.

Do not:

- Rewrite sentences.
- Correct scientific claims.
- Change numerical values.
- Change equations.
- Remove paragraphs.
- Add explanations.
- Translate the document.
- Add references.
- Remove references.
- Invent data.
- Invent results.
- Invent figures.

Minor transformations required solely to reproduce the visual appearance are allowed.

For example:

\textbf{important}

must become bold text.

However, the underlying wording must remain unchanged.

---

# Mathematical rendering

Mathematical content must be rendered as mathematics rather than displayed as raw LaTeX.

For example:

$E = mc^2$

must appear as a properly typeset mathematical expression.

Display mathematics such as:

\[
E = mc^2
\]

must be rendered as a separate mathematical block.

Numbered equations such as:

\begin{equation}
F = ma
\end{equation}

must retain their equation numbering.

The renderer should correctly represent common mathematical constructs used by the reports, including:

- Fractions.
- Superscripts.
- Subscripts.
- Greek letters.
- Vectors.
- Integrals.
- Derivatives.
- Matrices.
- Limits.
- Sums.
- Products.
- Mathematical symbols.
- Scientific notation.
- Units.

Never expose raw mathematical commands in the final PDF when they can be rendered visually.

---

# Units and `siunitx`

The reports may use the `siunitx` package.

Examples include:

\SI{3}{\electronvolt}

\SI{2.4}{\meter\per\second}

\si{\angstrom}

These must be rendered as human-readable scientific units.

Do not display raw `siunitx` commands in the final PDF.

The visual representation should preserve the scientific meaning of the source.

---

# Figures

For every figure referenced by `main.tex`:

1. Locate the corresponding image.
2. Load the original file.
3. Preserve its aspect ratio.
4. Apply the requested dimensions.
5. Place it approximately where the source specifies.
6. Render its caption.
7. Preserve figure numbering when applicable.

The template convention is approximately:

[H]
width=0.55\textwidth

unless the source explicitly specifies another size.

Figures must not be replaced by text placeholders.

If a referenced figure is missing, report the missing file instead of generating an artificial substitute.

---

# UEV logo

When the UEV logo block exists in the source template, render:

assets/LogopequeUE.jpg

in the position specified by the template.

The logo must not be omitted merely because the renderer is not performing a traditional LaTeX compilation.

If `informe` deliberately removed the logo block, do not reintroduce it.

---

# Title page

The title page must reproduce the information and structure specified by the template.

Respect:

- Subject.
- Title.
- Author.
- University.
- Degree.
- Logo.
- Spacing.
- Alignment.
- Decorative elements.

Do not invent title-page information.

The title page should visually resemble the corresponding page generated by the original template.

---

# Sections and hierarchy

Preserve the hierarchy:

\section
\subsection
\subsubsection

Each level must have its corresponding visual style.

Do not flatten all headings into a single style.

The hierarchy must remain visually obvious in the final PDF.

---

# Paragraphs and indentation

The source generated by `informe` uses explicit `\noindent` rules.

Respect the intended effect of:

\noindent

Do not introduce unwanted first-line indentation where the source explicitly disables it.

Line breaks such as:

\\

must be represented visually as line breaks.

They must never appear literally in the final PDF.

---

# Tables

Render LaTeX tables as actual tables.

Preserve:

- Rows.
- Columns.
- Cell content.
- Alignment.
- Borders when present.
- Mathematical expressions.
- Units.
- Captions.
- Table numbering when applicable.

Do not convert a table into an unformatted block of text.

Tables must remain readable and must fit within the page whenever possible.

---

# References

Render the bibliography as a properly formatted reference section.

The source may use:

\begin{thebibliography}{...}

or another bibliography structure.

Preserve:

- Authors.
- Years.
- Titles.
- URLs.
- Source information.
- Reference numbering.

Do not invent missing bibliographic information.

When possible, preserve clickable URLs in the final PDF.

---

# Page layout

The renderer must generate a real multi-page document rather than one continuous page.

It must:

- Create pages automatically.
- Respect the template's margins.
- Break paragraphs naturally.
- Avoid cutting text through the middle of a line.
- Keep figures and captions together whenever practical.
- Avoid unnecessary blank pages.
- Keep tables readable.
- Maintain page numbering.
- Respect the document's page structure.

The final document should resemble a professionally typeset university report.

---

# Page breaks

Explicit commands such as:

\newpage

and:

\clearpage

must be respected.

Do not arbitrarily remove explicit page breaks.

---

# Lists

Interpret common LaTeX list environments such as:

\begin{itemize}
...
\end{itemize}

and:

\begin{enumerate}
...
\end{enumerate}

as actual formatted lists.

Preserve:

- Item order.
- Indentation.
- Bullet or numbering style.
- Nested lists where present.

Do not expose the environment commands in the PDF.

---

# Text formatting

Interpret common text-formatting commands used by the template, including where applicable:

\textbf{}
\textit{}
\underline{}
\emph{}
\texttt{}

and reproduce their visible effect.

Formatting commands must not appear literally in the PDF.

---

# Rendering errors

If a LaTeX command cannot be interpreted directly, reproduce its closest faithful visual equivalent.

For example, if a package-specific command is not directly supported, reproduce the visible effect that command is intended to create.

Do not display unsupported commands as raw text merely because they cannot be interpreted directly.

If a command has no clear visual equivalent, preserve the underlying textual content and avoid silently deleting information.

---

# Unsupported functionality

The renderer is not required to implement the complete LaTeX language.

It is required to correctly reproduce the functionality used by:

- assets/plantilla.tex
- The `informe` skill.
- Reports generated using that template.

Priority should be given to:

1. Template formatting.
2. Text.
3. Sections.
4. Mathematics.
5. Figures.
6. Tables.
7. References.
8. Page layout.
9. Logo.
10. Code listings.

If unsupported functionality is encountered, attempt a visually faithful representation without changing the academic content.

---

# Code listings

If `informe` has included Python or Mathematica code using `lstlisting`, render the code as a formatted code block.

Preserve:

- Code text.
- Indentation.
- Line breaks.
- Language-specific formatting where possible.

Do not execute the code.

The renderer's purpose is to display the code, not evaluate it.

For Python:

\begin{lstlisting}[language=Python]
...
\end{lstlisting}

must appear as a formatted Python code listing.

For Mathematica, respect the style defined by the corresponding template configuration.

# Visual quality control

Before delivering the PDF, perform a final visual and structural inspection.

## Document

Verify:

- The PDF exists.
- The PDF opens correctly.
- The page count is plausible.
- No pages are unexpectedly empty.
- The document is actually readable.

## Title page

Verify:

- Correct title.
- Correct subject.
- Correct author.
- Correct university.
- Correct degree.
- Correct logo when enabled.
- Correct general layout.

## Text

Verify:

- No raw LaTeX commands are visible.
- No paragraphs are missing.
- No obvious duplicated text exists.
- No text is unexpectedly truncated.
- No accidental source-code fragments are visible.

## Mathematics

Verify:

- Equations are visible.
- Symbols render correctly.
- Equation numbering is preserved where applicable.
- Fractions and superscripts render correctly.
- Units are readable.
- No raw mathematical LaTeX remains visible.

## Figures

Verify:

- All referenced figures are present.
- No broken-image placeholders appear.
- Images preserve their aspect ratio.
- Captions are present.
- Figure numbering is preserved where applicable.

## Tables

Verify:

- All rows and columns are present.
- Text is not clipped.
- Mathematical content remains readable.
- Tables do not unexpectedly overflow the page.

## Layout

Verify:

- Heading hierarchy is correct.
- Margins resemble the template.
- Page breaks are sensible.
- Paragraph indentation is correct.
- Figures are appropriately positioned.
- No unexpected blank pages appear.

## References

Verify:

- The bibliography is present when required.
- References are readable.
- Reference numbering is preserved.
- URLs are not visibly corrupted.

# Fidelity priority

When exact reproduction is not possible, prioritize fidelity in this order:

1. **Academic content**
2. **Document structure**
3. **Mathematical correctness**
4. **Figures and tables**
5. **Template layout**
6. **Typography**
7. **Fine spacing**

Never sacrifice academic content merely to achieve visual similarity.

---

# No LaTeX compilation requirement

This skill must not depend on the user having installed:

pdflatex
latexmk
xelatex
lualatex
TeX Live
MiKTeX

The objective is to generate the PDF using the document-generation and PDF-rendering capabilities available in the execution environment.

The existence of a LaTeX compiler is therefore **not a prerequisite**.

If a LaTeX compiler happens to be available, it may be used only if it improves rendering fidelity and is supported by the environment. It must not be treated as a required dependency.

The user must not be asked to install a LaTeX distribution merely to use this skill.

---

# Source integrity

The renderer must never overwrite or destroy the original LaTeX project.

The following source files must remain intact:

main.tex
assets/
Figures/

The generated PDF is an additional output.

If temporary processing files are created, they must not replace the original source.

---

# Output

The principal output is:

main.pdf

The PDF is the final user-facing artifact.

The source project remains available separately:

main.tex
assets/
Figures/

The renderer must provide the final PDF to the user after the quality-control stage.

Do not claim that the rendering was successful unless the final PDF has actually been generated and verified.

If the PDF cannot be generated because an essential source asset is missing or the available rendering mechanism cannot reproduce a required element, report the exact problem instead of pretending that the document is complete.
